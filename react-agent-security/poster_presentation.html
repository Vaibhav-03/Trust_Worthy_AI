① The Problem

ReAct agents interleave reasoning with tool calls. LLMs cannot architecturally distinguish trusted user instructions from untrusted tool outputs — so adversarial text inside a web page, document, or API response can hijack the agent.

OWASP LLM01:2025 ranks Indirect Prompt Injection as the #1 vulnerability for LLM applications. Real-world exploits: Slack AI exfiltration (Aug 2024), M365 Copilot EchoLeak (CVE-2025-32711), GitHub Copilot RCE (CVE-2025-53773).

Threat Model

Setup: LangGraph create_react_agent, temp=0, 4 tools (web_search, file_reader, calculator, email_sender). 15 tasks × 12 attack configs = 180 trials per model.

Phase 2 Findings

▸ Position determines stealth, not success. Prefix 73.3% vs suffix 77.8% ASR — but suffix has TCDR=0%, harder to detect.
▸ Authority framing is overrated. "SYSTEM NOTE:" framing (74.4%) ≈ plain imperatives (76.7%). Fake system messages give no real edge on Llama.
▸ Web-search tasks are maximally vulnerable. Tasks 4, 13, 15 → ASR=100% under every configuration.
▸ TCDR is a useless detector. Standard tool-call anomaly monitoring catches <5% of successes. Destination-level audit logging is the only reliable signal.

⑥ Takeaways

  • Unprotected ReAct agents are critically vulnerable — and silently. ASR 75.6% co-occurs with TCR 62.9%.
  • Tool-level wrappers beat prompt-level rules. Recipient locking + goal verification: ASR=0, zero utility cost.
  • Grounding ≠ free. Augmented prompts catch 96% of attacks but cost +13.3% net FPR; additive phrasing leaks through.
  • Audit logging detects 78% post-hoc — model-dependent (drops to 1% on Gemma when emails get blocked upstream).
  • Defenses don't port for free. goal_verification leaks 7× on Qwen3-235B due to tool-call format differences.
  • FPR < 0.30 should gate any security eval — Qwen3-235B's 47% baseline failure rate makes its security numbers meaningless.
